Start a new project with the technical team:

$ARGUMENTS

You are the lead: follow `${CLAUDE_PLUGIN_ROOT}/agents/team-lead.md` §1 and §3–§6 — Read it if you are not already the lead. Empty request → resume from `.team/STATE.md`, or ask for the idea or PRD path. Not a git repo → ask the user to run `git init` first.

0. **Task list** — before the first spawn, put the steps below on the session's task list, one item per step (`update_plan` in the desktop app; `TaskCreate`/`TaskUpdate` in the CLI, loaded via ToolSearch if deferred; else `TodoWrite`), and keep it current (lead §3 *Task list*). No task tool → carry on: `.team/items/` is the truth and the list is rebuilt from it on resume.
1. **Requirements** — `technical-team:team-ba` writes `.team/PRODUCT.md` and the MVP `.team/requirements/<slug>.md`. Show its questions to the user and wait.
2. **Stack + design** — in parallel: `technical-team:team-architect` proposes 2–3 options with one recommended for each stack choice the user left open (a stack the user named is a decision: record it in an ADR), writes `ARCHITECTURE.md` and the ADRs (numbers from the lead); `technical-team:team-designer` (if there is UI) writes `frontend-design/DESIGN.md` and the MVP screen spec `frontend-design/<slug>.md`. Show the user and wait for the stack choice.
3. **Plan** — `technical-team:team-architect` writes `.team/system-design/<slug>.md`; `technical-team:team-pm` writes the tickets in `TASKS.md` grouped by milestone (`<KEY>-M1` = walking skeleton: build, lint, test runner, one end-to-end slice). **Workflow opt-in** — the Workflow tool is available (also if deferred) AND the user typed a slash command of this plugin for this item (this command, or `/technical-team:run`, which hands the chosen pipeline to the lead) → run the workflow. Otherwise (no tool, or the lead was started without a slash command) → run the steps inline below. Workflow run (load `technical-team:run-kit` if not loaded): call Workflow with `name: 'technical-team:team-plan-tickets'` (`${CLAUDE_PLUGIN_ROOT}/workflows/plan-tickets.js`) and `args` = `{slug, key, pmBrief, maxRounds, context, root}` (`key`: the item's `key`; tickets must be `<KEY>-T<n>`). pm writes `.team/TASKS.md`; the script checks ids, roles, files, ACs, dependencies, group order and file overlap in code and sends violations back to pm (up to `maxRounds`, default 2). In the pm brief ask for a `milestone` and a `group` number per ticket (groups are numbered per milestone), and keep done tickets that others depend on listed, not collapsed, until the item closes. `done` → step 4's build-loop for milestone i takes `milestones[i].groups` as `args.groups` (add one brief per ticket). Route the rest per run-kit §6 (`stuck` has empty `milestones`). Show the milestones and wait for OK.
4. **Build** — per milestone, on its tickets: qa pre-check (`technical-team:team-qa`, before any code) → build (`technical-team:team-developer`) → review (`technical-team:team-code-reviewer`, plus `technical-team:team-security` when feature.md step 7 says so) → test (`technical-team:team-qa`), as steps 5–8 of `${CLAUDE_PLUGIN_ROOT}/commands/feature.md`. Each milestone is its own item (`<slug>-m<n>`, own round and findings). When the **Workflow opt-in** of step 3 holds: one call of `${CLAUDE_PLUGIN_ROOT}/workflows/build-loop.js` per milestone, built as feature.md's build loop, `args` = `{item, groups, reviewBriefs, qaPlanBrief, qaBrief, root, context}` (no `writerBrief`: docs stay in step 5); write `item` back first, then route per run-kit §6. A pre-check spec issue stops the milestone before any build (feature.md step 5). One task-list item per milestone; never skip review or test. After each milestone show what works and how to run it; wait for OK.
   **Milestone close** — before the next milestone, compact the specs it touched: opt-in holds → call Workflow with `name: 'technical-team:team-compact'` (`${CLAUDE_PLUGIN_ROOT}/workflows/compact.js`) and `args` = `{files, context}` (`files`: `[{path, owner}]`, e.g. `.team/system-design/<slug>.md` → architect); inline → each owner rewrites its file to current truth, an independent agent checks nothing was lost. Then close the milestone's item (run-kit workspace § Item state).
5. **Ship** — `technical-team:team-devops` adds CI and run/deploy files; `technical-team:team-writer` writes the README; then run `${CLAUDE_PLUGIN_ROOT}/commands/release.md` with version `0.1.0`. Its step 1 re-runs only the gates whose code changed since the last milestone passed.
6. **Close** — lead §6.

Do not deploy, tag, commit or push unless the user asks; give the user the commands.
